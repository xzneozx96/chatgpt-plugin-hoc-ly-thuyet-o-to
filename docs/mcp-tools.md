# MCP tools

`get_question({ questionId?, afterQuestionId?, beforeQuestionId?, topic? })` returns one original bank question without its answer. `questionId` opens a specific ID; `afterQuestionId` advances; `beforeQuestionId` goes back; `topic` chooses one of seven exam categories. Image questions include an `imageUrl`. This tool displays the MCP Apps quiz UI.

`submit_answer({ questionId, selectedAnswer, attemptId? })` scores A, B, C, or D against the bank. It returns the correct answer, source explanation or an explicit missing-explanation message, plus `nextReviewAt` when progress storage is enabled. Clients should use a stable UUID `attemptId` for retries. Reusing an ID for a different answer is rejected.

`search_theory({ query, limit? })` searches only `question-bank.json` and returns question ID, topic, source reference, question text, and a source excerpt. An empty `hits` array means the bank has no match.

`find_teacher_explanation({ questionId?, query?, limit? })` returns Thầy Tâm's explanation from the approved teaching book: `notes[]` with `quotes` (his words, each with a `timestamp` such as `V1 26:10` and a YouTube `url` with `&t=`), `summary`, `relatedTip`, `segments` (video, start, end, `url`) and `sourceNote`. Pass `questionId` (for example `q019`) or a Vietnamese `query`; a query is matched to bank questions locally with the `search_theory` ranking (default 2, max 3 questions) and each question's book pages are then read. Empty `notes` means the book has no teacher explanation for it. Timestamps and links come from the book's text and video table, never from the model. Questions in a running mock test are skipped. The tool exists only when `AEGIS_MCP_TOKEN` is set on the server (optional `AEGIS_MCP_URL`, default `https://aegis-api.minastik.com/mcp-apps/`). The token stays server-side because plugin `mcp.json` headers are literal, visible package data. `app/src/content/aegis-book-map.json` maps each question to its book page and each video code to its YouTube ID; rebuild it with `AEGIS_MCP_TOKEN=… node scripts/build-aegis-page-map.mjs` if the book is re-uploaded.

`get_progress({})` and `get_due_reviews({ limit? })` are available in the private local trial and the authenticated public MCP. The latter returns due questions without answer keys. The public MCP also exposes `delete_my_progress({ confirm: true })` to remove the signed-in learner's saved attempts. The anonymous public demo exposes none of these three tools.

## Learning tools

These tools serve the learning card (`ui://ly-thuyet-lai-xe/learning-….html`). Every tool that changes saved state takes a `requestId` UUID. A retry with the same ID and payload returns the saved result without saving again; the same ID with a different payload is rejected with `REQUEST_CONFLICT`. Without saved history (the anonymous public demo), only `get_course` and `list_units` exist.

Every learning tool also accepts `caller: "card"`. The card sets it on its own calls. The result is the same, but its text only tells ChatGPT that the card is showing it and to stay silent. Without the marker, the text carries the full text-only reply: the verbatim question, the verdict and what to call next. The marker is not part of the request, so a retry with or without it matches.

A failed learning tool returns `isError: true`, Vietnamese text for ChatGPT, and `structuredContent: { kind: "error", code }`, so the card can word its own message. Codes include `LIGHTNING_EXPIRED`, `LIGHTNING_NEEDS_HISTORY`, `LEAGUE_NEEDS_LESSON`, `LEAGUE_NAME_INVALID`, `LEAGUE_NAME_REJECTED`, `LEAGUE_NOT_JOINED` and `LIBRARY_UNAVAILABLE`.

`get_course({})` returns the course view: `covered`, `learned` and `dueCount` (Đã gặp, Đã thuộc, Cần ôn hôm nay) out of 600, `onTheWay` (questions with one qualifying correct answer, not learned yet, never part of `learned`) and `nextLearnAt` (the earliest time one of them can count again, or `null`), `wrongToday` (Sai hôm nay: questions answered wrong today in the learner's timezone, each counted once), `newToday` and `dailyGoal` for the goal ring, `forecastFinishAt`, `units` (the seven bank categories with `covered`, `learned`, `onTheWay` and `due`), `customCategory` (Câu hỏi dễ nhầm lẫn, with `familyCount`, `onTheWay` and `due`), `xp { total, today, week, weekStartsAt, weekEndsAt, suspicious }`, `tomorrowDue`, and `leagueSummary`, which is `null` until the learner can join, then `{ joined, rank, weekXp }`.

`get_today_mistakes({})` returns `{ kind: "mistakes", items }`, newest first. Each item is `{ question, chosen, correctAnswer, explanation, at }`, where `question` is the original question without its key, `chosen` is the learner's latest wrong choice today, and `explanation` is the bank text or `null`. It is read-only: it records no attempt and no help. The card opens it from the Sai hôm nay tile.

`list_units({ query?, kind?, offset?, limit? })` searches the seven categories and the 245 confusing-question groups by title or original question number, with or without Vietnamese accents. `limit` defaults to 20 and can be up to 300, so one call can return every group; the card's family picker does that. It returns a page of `units` with `questionCount`, `covered`, `learned`, `onTheWay`, `due` and `status` (`"bank"` for a category, `"approved"` for a group), plus three `suggestions`.

`update_profile({ requestId, dailyGoal?, timezone?, targetDate?, studyWeekdays? })` saves the study plan and returns the course view.

`start_study({ requestId, unitId?, questionIds?, count?, practice?, override?, reviewOnly? })` with no arguments reopens the latest open lesson (daily or topic) or starts the daily one: due reviews first, then the next never-answered questions in bank order up to the remaining daily goal. When a not-yet-learned family sibling exists, the daily lesson ends with one compare-the-pair challenge. `reviewOnly` runs just the due reviews. Once reviews are done, `count` alone (10, 12 or 15 in the card) starts its own lesson of that many never-answered questions, with no daily-goal cap. `unitId` with `count` studies the never-answered questions of that bank category and takes all that remain when fewer than `count` are left; `practice: true` studies already-answered questions of the unit instead and adds no new coverage. While any review is due, `unitId` and `count` starts fail with `REVIEWS_DUE`. An explicit `questionIds` lesson takes at most `count` questions, which defaults to the daily goal. `get_course` carries `openSession` (the latest unfinished lesson, or `null`) so the card can offer Tiếp tục.

`get_study_session({ sessionId })`, `submit_study_answer({ requestId, sessionId, questionId, answer, confidence? })`, `next_study_question({ requestId, sessionId })`, `skip_study_question({ requestId, sessionId })`, `pause_study({ requestId, sessionId })` and `resume_study({ requestId, sessionId })` return the study view. It includes the current `question`, `currentFeedback` after an answer (its `teachingStatus` is `teaching_gap` when the bank has no explanation for the question), `queue` (a skipped item has `skipped: true`), `xp` for the session, `combo`, `lastAward { xp, baseXp, bonusXp, reason, masteredNow }`, `itemKind`, `steps { review, new, practice, pairGroups }` for the intro, and `unit { id, title, family }` when the lesson came from a category or a confusing-question group (`null` otherwise). For the finish screen it also has `masteredCount`, `firstCorrectCount` (first answers in this session that counted toward Đã thuộc: correct, unassisted, not a guess), `assistedCount`, `guessedCount`, `skippedCount`, `skippedPending` and `goal { newToday, dailyGoal, dueCount, tomorrowDue, onTheWay, nextLearnAt }`. During a compare-the-pair step, `pair { group, title, axes, status, questions, feedback }` holds both questions. Answer each with `submit_study_answer`, in either order, then call `next_study_question` once. Each `feedback` entry stays `null` until both answers are in, then carries the verdict and its `award`. Every family has been reviewed and is `status: "approved"`. Its `axes` name what tells the two questions apart, and each question is explained from its own bank explanation.

While a lesson or lightning round is open, the result also has `_meta.lessonKeys` and `_meta.xpBudget`. `lessonKeys` maps each question ID in `queue` to `{ question, correctAnswer, explanation, teachingStatus, award }`, so the card can show verdicts and their XP before the server confirms them. `award` is `{ correct, guess, wrong }`: the award for answering that question now, unassisted and outside a repair step. `correct` and `guess` have the shape of `lastAward` (`{ xp, reason, masteredNow, baseXp, bonusXp }`), and `wrong` is the XP number. `xpBudget` is `{ practiceLeft, lightningLeft }`: practice XP left for the learner-local day out of 50, and lightning XP left in the round out of 15, or `null` outside a lightning round. `_meta` reaches the card but not the model. Mock-test results never carry keys.

`request_study_help({ requestId, questionId, sessionId?, helpKind? })` records assistance before any hint or explanation and returns the bank explanation. `set_question_confusion({ requestId, questionId, enabled })` sets or clears the learner's confusion flag.

`start_lightning({ requestId })` starts a 60-second lightning round over up to 30 questions the learner has answered before, as a study view with `mode: "lightning"`, `deadline`, `remainingMs`, `serverNow`, `correctCount` and `wrongItems`. Answer, then call `next_study_question`, for each question. The card sets `leftMs` on `submit_study_answer` and `next_study_question` to the time it showed as left at the click. A request with `leftMs` above 0 that arrives within 15 seconds after the deadline still counts, and moves the deadline to `leftMs` after its arrival, at most 3 minutes past the 60 seconds. Any other answer after the deadline fails with `LIGHTNING_EXPIRED` and saves nothing. Reading the session after the deadline closes the round. Once the round is over, `review` lists each wrong question with `chosen` and `correctAnswer`; while it runs, `review` is `null`. Without earlier answers the tool fails with `LIGHTNING_NEEDS_HISTORY`.

`start_mock_test({ requestId, mode? })`, `get_mock_test({ attemptId, requestId? })`, `save_mock_choice({ requestId, attemptId, questionId, answer })`, `finalise_mock_test({ requestId, attemptId, confirmUnanswered? })` and `abandon_mock_test({ requestId, attemptId })` run the 30-question, 20-minute test. `mode: "library"` fails with `LIBRARY_UNAVAILABLE` until a test library is supplied. A finalised test returns `score`, `passed`, `criticalFailures`, `results` per question (unanswered ones have `unanswered: true`) and `closedAt`.

`get_league({})`, `join_league({ requestId, displayName })`, `leave_league({ requestId })` and `set_league_hidden({ requestId, hidden })` return the league view: `{ kind: "league", joined, canJoin, displayName, hidden, weekStartsAt, weekEndsAt, daysLeft, rank, weekXp, rows: [{ rank, displayName, weekXp, you }] }`. Joining needs one finished lesson (`LEAGUE_NEEDS_LESSON`) and a display name of 3–20 letters, digits, spaces, dots, underscores or hyphens (`LEAGUE_NAME_INVALID`) that passes the profanity check (`LEAGUE_NAME_REJECTED`).
